# Kinetix — build plan

Hybrid running + strength training app for iPhone. This document records the
agreed architecture and milestones. It is updated as decisions change.

## Decisions

| Topic | Decision |
|---|---|
| Platform | iOS 17+, Swift + SwiftUI, iPhone only for v1 |
| Project file | Generated by **XcodeGen** from `project.yml` (the `.xcodeproj` is not committed) |
| Storage | **SwiftData**, offline-first. Every record has `id`, `updatedAt`, `deletedAt`, `needsSync` |
| Sync | Supabase, last-write-wins per record, soft deletes; built for multiple devices |
| Plan horizon | Outline (blocks + weekly targets) to the event; detailed sessions generated ~2 weeks ahead |
| Run effort | Asked after each session (pre-filled default from session type) → sRPE load |
| Templates | JSON files in `Packages/TrainingEngine/Sources/TrainingEngine/Resources/` (run workouts, exercises, strength programmes, plan rules); format allows a remote override later |
| Plan start | This week if onboarding finishes Mon–Wed, otherwise next Monday |
| Rest day | Always at least one; choosing 7 days makes Friday a rest day |
| Units | Stored internally as metres / seconds / kg; units only affect display |
| Secrets | `Config/Secrets.xcconfig` (git-ignored); see `Secrets.example.xcconfig` |
| Subscriptions | Not designed yet. A single `Entitlements` service will gate features (StoreKit 2), so a paywall can be added without restructuring |
| Watch app | Out of scope for v1; the engine is UI-free so a Watch target can reuse it |
| CI | GitHub Actions: engine tests on Linux + macOS, app build + tests on an iOS simulator |

## Architecture

```
Packages/TrainingEngine/     Pure Swift (Foundation only), fully unit-tested
  Domain/                    Profile, sessions, pace, units, run/strength structures
  PaceZones                  race/5k time → pace zones (Daniels VDOT)          [M2]
  PlanGenerator, Scheduler   templates → blocks → weeks → sessions; interference rules  [M2]
  Progression                double progression, stalls, deloads, explanations [M3]
  PaceCoach                  smoothed pace → cue decisions (delay, cooldown)    [M4]
  LoadModel, Rebalancer      sRPE load, ACWR traffic light, skip/swap rebalancing [M5]
  Templates/*.json           run session types, strength programmes, exercises  [M2]

Kinetix/ (iOS app)
  App/                       entry point, root view, navigation (AppRouter)
  DesignSystem/              KXColor, KXFont, KXSpacing + components
  Persistence/               SwiftData models ↔ engine types
  Services/                  Location, Speech/Audio, HealthKit, BLE HR, Sync, Strava  [M4, M7, M8]
  Features/                  Onboarding, Home, Plan, Progress, Session trainers, Settings
```

## Data model (SwiftData)

- **UserProfileModel**: onboarding answers (maps to `AthleteProfile`)
- **CoachingSettingsModel**: cue delay (default 20 s), tolerance, voice, volume, toggles
- **TrainingPlanModel** → **PlannedSessionModel**: date, slot, kind, key flag, status
  (planned/completed/skipped/swapped), change reason, run structure / strength prescription
- **PlanChangeModel**: one-sentence explanations of plan changes
- **RunLogModel**: route, splits, HR, time in target, effort, load
- **StrengthLogModel** → **SetLogModel**: per-set weight, reps, RPE
- **ExerciseStateModel**: working weight, rep range, stall count, last change reason
- **PersonalRecordModel**, **RecoveryCheckInModel**
